The engineering project is carried out in groups of 2 to 3 people.
The engineering project can be carried out using robots or simulation (simulation modelling) programmes.
The group of students decides for themselves what task the robot should perform.

The main requirements for the task are as follows:

    several robot action execution and decision-making algorithms must be used, i.e. the robot must perform different actions under different conditions;
    at least several robot sensors must be used;
    the scope of the project must be greater than that of the laboratory work performed.

    Sample project ideas: robot police officers catching offenders; robot battles; games using robots; overcoming various mazes using as many sensors as possible, etc.


The defence of the engineering project will take place during the 14th-15th week of the semester during practical or laboratory work. The day before the defence, it is mandatory to upload the engineering project report (pdf), presentation (pdf) and, if the task was carried out in a simulated environment, the model file to Moodle.

# General Criteria for Evaluating the Engineering Project
## 1. Technological Complexity of the Solution (Robot Control Algorithm) and Correct Task Execution

Includes demonstration of robot control (via video recording, virtual environment presentation, etc.), oral presentation of the project, and responses to teachers’ questions — evaluated from 0 to 10 points.

To assess the level of complexity of the engineering project, the following criteria are considered:

    Originality and scope of the project idea – whether the project task goes beyond the scope of standard laboratory assignments;

    Complexity of the robot control algorithm – whether multiple robot action execution and decision-making algorithms are used, i.e., whether the robot performs different actions under different conditions;

    Use of robot sensors – whether the robot’s movement control employs as many sensors as possible;

    Preparation of the robot’s movement environment – whether students create and build the environment themselves (e.g., model, obstacles) or use an existing environment (e.g., a testing environment in a specific tool).

## 2. Quality and Completeness of the Project Report:

1. Cover page -    0.1
2. Table of contents - 0.1
3. Engineering project task - 0.2
4. Analysis of task requirements and robot control (mission) scenario - 1.0
5. Description of the robot or model in a simulation environment (components, technical specifications, photos) - 1.0
6. Robot control program code with detailed comments - 2.0
7. Experimental testing of robot control and its description (e.g., different test scenarios, result comparison — control accuracy, task completion speed, etc.) - 5.0
8. Conclusions (each group member formulates individual conclusions and states their personal contribution to the project) - 0.5
9. List of references (including online sources, forums, etc.) - 0.1

## 3. Quality of the Illustrated Oral Presentation

The oral illustrated presentation should include:

    Presentation of the engineering project’s task and idea;

    Description of the sensors used for the task (or, if the robot is newly built – detailed structure of the robot) or detailed description of the model in the simulation environment;

    Preparation of the robot’s movement environment;

    Experimental testing of robot control and obtained results;

    Conclusions and contributions of each group member;

    Demonstration (video, live demonstration, or simulation environment).

The oral illustrated presentation with demonstration should last 10 minutes.

Note:
The engineering project evaluation consists of two separate grades in the AIS – one for the written report (IR) and one for the oral presentation (ŽP).
